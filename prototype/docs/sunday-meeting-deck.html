Sunday team meeting · 7 Sep 2026

Once upon a time,
a 30M model learned the next word.

This is our status from day one. We are building a causal language model on TinyStories-v2: it reads a child’s story and guesses the next token. It is not a spam classifier, not SMOTE, not 99% accuracy.

Plan: train a matched 31.4 million parameter body twice. First mixer = attention (baseline, 10 epochs done). Second mixer = TTT-Linear (test-time training memory, not started). Same width, depth, vocab, optimizer. Only the memory mechanism changes.

Say this opening: “We taught a small story model to predict the next word. Attention works. TTT is the experiment still ahead.”

What we are actually optimizing

The exam is always: what token comes next?

Every training step takes a 256-token chunk of TinyStories. The model sees tokens 1…t and must name token t+1. Loss is cross-entropy. The gold-colored triangle in the background is a causal mask: the model is forbidden to look at the future. That is the whole scientific claim of this project.

  • Fair comparison. One skeleton (512 hidden, 8 layers, 8 heads, SwiGLU 1536, 8k vocab). Swap only the mixer: softmax attention vs TTT-Linear inner-loop memory.
  • Real win. Validation perplexity falls (how surprised the model is on held-out stories) and entropy stays high enough that it still uses many words.
  • Fake win we reject. Token match near 99% with entropy near zero means the model collapsed to a few tokens. That is a broken LM, not a good classifier.
Architecture we locked

One body, two kinds of memory

We threw away the old ~17M checkpoints. They were a different shape and cannot resume into this run. The 30M recipe:

  • ~31,367,680 parameters · hidden 512 · 8 layers · 8 heads · SwiGLU intermediate 1536
  • Tokenizer vocab 8,000 · sequence length 256 · batch 2 × grad-accum 2 on Kaggle T4
  • Optimizer AdamW β = (0.9, 0.95) · L2 = weight decay 0.1 on matrices only (bias and LayerNorm/RMSNorm are not decayed)
  • Dropout 0.1 from scratch; 0.05 when we continue a plateaued run so it can still fit

Attention — finished 10 epochs

Classic QKᵀ softmax over the 256-token window. This is the baseline the paper-style comparison needs. Weights: last.pt at step 101,936.

TTT-Linear — not started

Test-time training: a small linear memory updated inside the forward pass. Same 31.4M budget. New folder ttt-linear-30m. Never load attention last.pt into it.

Chronology since day one

How we actually got a working story model

1. Prototype. We wrote tttmem: CausalLM, RoPE, SwiGLU blocks, next-token loss, collapse metrics, Streamlit so you can type “Once upon a time” and hear the model continue the tale.

2. Laptop then Colab. Attention 30M reached about step 31,000 (still epoch 1). Val perplexity ~10.5, token match ~51%. Alive, not collapsed, but not finished.

3. Kaggle. Colab Drive and zip names fought us. We moved to Kaggle datasets (src30m + last.pt). Ten epochs completed. The file we resume is ~376 MB at epoch 10 / step 101,936.

4. Fit, not more L2. Train and val are close (epoch-7 train CE ~1.56 vs val ~1.72). Raising weight decay would usually hurt this model. The continue-fit recipe is more epochs, dropout 0.05, cosine LR floor 10% of peak.

5. Hardware lesson. Current Kaggle PyTorch has no kernels for Tesla P100 (sm_60). Training must be GPU T4 (sm_75). We already confirmed T4 + new train.py (16,239 bytes) + ckpt.py.

How not to misread the scoreboard

Fifty-nine percent is a healthy storyteller

The vocabulary has 8,000 pieces. Guessing the exact next TinyStories token ~59% of the time is strong next-word prediction. A human would not score 99% either. If we ever saw ~99% match with entropy below 1.2, the model would be stuck saying the same few words — we coded that as collapse, and it stayed off.

Collapse rule (in the trainer). Flag only if entropy < 1.2 and (top-1 mass > 0.9 or token match > 0.85). We never met that. Unique predicted tokens stayed in the hundreds per batch.

Underfit vs overfit. Epoch-7 mean train loss ~1.56 versus val ~1.72. Small gap. This is not a model that memorized train and failed val. Extra L2 on the loss, or weight decay ≫ 0.1, would typically raise val PPL — the opposite of what we want.

Say this: “If someone asks why accuracy is not 99%, the answer is: because this is language modeling, and 99% would mean we broke it.”

What landed in the repository

The experiment is encoded, not just trained

Teammates can clone the prototype and run the same protocol. The important pieces:

  • tttmem/ — CausalLM, attention or TTT-Linear mixer, RoPE, RMSNorm, SwiGLU.
  • scripts/train.py — AdamW + decoupled L2, cosine LR with a 10% floor, collapse checks, train-eval vs val gap, refuse mixer/size mismatch on resume, refuse Pascal GPUs.
  • scripts/pack_ckpt.py — Windows cannot torch.load an unzipped last/ folder; we zip it back to last.pt.
  • notebooks/kaggle_train_30m.ipynb — cell 1 copies code and weights; cell 2 is the training job.
  • app.py — Streamlit inspect: val curves and generation from “Once upon a time”.

Push code to GitHub. Do not git-add the 376 MB checkpoint (GitHub cap 100 MB). Share weights on Kaggle Output or Drive.

What ate the calendar (so we do not repeat it)

Ops failures, not science failures

  • JSON in a code cell. Opening kaggle_train_30m.ipynb in Notepad and pasting it into Kaggle runs execution_count: null. Python has no null. Upload the notebook or paste only the Python.
  • Stale zip. The 1 Sep src30m.zip had data but no ckpt.py. We rebuilt it. Cell 1 must print has ckpt.py True and train.py bytes 16239.
  • Wrong GPU. P100 looks like “a GPU” but this torch build only runs sm_70+ (T4). First embedding call dies with “no kernel image.” Settings → Accelerator → GPU T4, then restart.
  • Wrong cell. Cell 1 stopping at READY is success. Training is the second cell and must stay running for hours. Save Version or Output wipes /kaggle/working.

What we need from the team today

Four decisions, then we keep training

  • Metrics. We report val loss, perplexity, entropy, token match, collapse flag. We do not report “accuracy 99%.”
  • Regularization. L2 stays AdamW weight decay 0.1. Nobody adds a second L2 term on the logits or raises decay “to fight underfitting.”
  • Ownership. One person owns the Kaggle T4 session and Save Version. Everyone else reviews logs, not live cells.
  • Sequence. Lock attention continue-fit → then TTT-Linear 30M → then compare PPL. Weights stay off GitHub; code goes on GitHub.

Close with: “Attention already tells TinyStories. The research question is whether TTT-Linear tells them better at the same 31 million parameters.”
